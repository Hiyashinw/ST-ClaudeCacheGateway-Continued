自动不发送 ttl；5 分钟和 1 小时统一应用对应的 Claude 原生窗口；手动模式按两种 marker 分别使用 1h / 5m。

使用指南

快速开始 客户端接入 缓存标记 断点保留 Prefix 锁定 缓存转译 渠道 高级配置 诊断 常见问题

快速开始

  1. 启动网关，确认控制台地址为 http://127.0.0.1:8788/console。
  2. 在酒馆 / 客户端里选择 OpenAI-compatible / Chat Completion 接入。
  3. Base URL 填 http://127.0.0.1:8788/v1，API Key 填你的上游供应商 Key。

酒馆里选择的是“入站格式”，决定客户端用哪种协议发给本地网关；控制台里的“上游格式”决定网关再用哪种协议转发给供应商。两者可以不同，例如酒馆用 OpenAI-compatible 接入，网关再按当前渠道设置转发到 OpenAI-compatible 或 Anthropic native 上游。

客户端接入

  • 本机使用：http://127.0.0.1:8788/v1
  • 不要把 API Key 写进渠道 Profile。Key 应放在客户端的 Authorization / x-api-key，或仅在私有机器上用 UPSTREAM_API_KEY 环境变量。

缓存标记

在稳定的大段内容末尾放置 [[CACHE_BREAK]] 或 [[CACHE_BREAK_SHORT]]，网关会移除标记并注入 Claude prompt cache 的 cache_control。

  • 自动断点设为“开启”时，会为最终 SYSTEM 末尾和每个 ASSISTANT 消息生成候选 marker；设为“自动”时，仅在请求没有任何手写 marker 和已有的合法 cache_control 时生成。
  • 适合放在标记前：系统提示词、角色卡、蓝灯世界书、长设定、固定规则。
  • 适合放在标记后：绿灯世界书、最近聊天、当前输入、短期记忆、会频繁变化的内容。
  • TTL 设为“手动”时，[[CACHE_BREAK]] 固定使用 1h，[[CACHE_BREAK_SHORT]] 固定使用 5m；其他 TTL 模式下两种标记都跟随全局设置。
  • Claude 每次请求最多支持 4 个缓存断点；两种 marker 和已有 cache_control 共用预算，多余标记会被移除。

固定头与缓存锚点

启用新策略后，网关按“固定头 → 锚点 → 最新普通尾点”的顺序分配最多 4 个缓存点。

  • 固定头缓存点设为 1 时，最前面的候选断点不会再随总断点数量增长而被挤掉。
  • 单锚点会记住新上下文最终入选断点中、排除固定头后的第一个 marker 断点；只要该点之前的完整前缀不变，就持续保留。
  • 滚动锚点会冻结首次实际入选的全部非固定点；普通上下文增长不会移动其中任何一点。首次固定下来的最后一个点会作为保护尾锚点，只有进入待淘汰状态后才会释放；达到设定间隔后，只用一个新点替换最老滚动点，其余位置保持不变。
  • 固定头为 A、间隔为 3 的轮换示例：A / E / F / G → A / E / F / G（间隔未到） → A / F / G / J（只替换 E）。
  • 固定头、锚点、普通尾点以及调用方已有的 cache_control 共用上游 4 点预算。例如固定头为 1、单锚点占 1 点时，长示例只会选择 A / F / O / P，不会再加入第五个 N 点。
  • 可开启“末锚点自动使用 5 分钟”，让最末网关锚点使用 5m，而前面的 1h 锚点保持不变。
  • “忽略末尾锚点”设置数字时会严格排除最新 x 个网关候选；评估模式先把 x 设为 0，连续 3 次同渠道、同协议、同模型的成功对话后，根据最早发生变化、新增或缺失的块一次性计算结果。0–5 自动填入，6 以上先提示检查预设，再由你选择仍然填入或重新评估。
  • 策略设置会持久保存，但已学习锚点只存在内存中；重启、更改策略或前缀变化后会重新学习。
  • 锚点模式与 Prefix Lock 互斥，最后启用的功能生效。

Prefix 锁定 / 强制锁定

Prefix 锁定用于处理“前缀漂移”：如果世界书、正则、插件或数据库填表内容在缓存点前产生变化，缓存命中率会下降。

  • 开启后，第一个带缓存点的请求会教会网关稳定前缀。
  • 后续请求会用已学习的前缀替换当前请求的缓存点前内容，缓存点后的聊天、输入、绿灯世界书仍保持最新。
  • 它是替换，不是追加，不会把世界书、系统提示词或角色卡重复拼接。
  • 更换角色卡、世界书、预设或缓存点前内容后，请清空并重新学习。
  • 关闭“缓存转译”后，Prefix 锁定也会跳过。
  • Prefix Lock 与缓存锚点互斥：启用 Prefix Lock 会关闭锚点，启用锚点会关闭并清空 Prefix Lock。

缓存转译与 TTL

  • “缓存转译”开启时，网关会处理两种缓存 marker、注入 cache_control，并允许 Prefix 锁定参与。
  • 关闭后，网关不做缓存标记转译，也不会执行 Prefix 锁定；但渠道、高级配置、上游格式转换仍然生效。
  • “系统身份消息处理”的默认模式不改 OpenAI-compatible 顺序，并在转为 Anthropic native 时执行保序映射与同角色合并；关闭 Anthropic 优化只让转换链统一上移 SYSTEM；全局上移模式则连 OpenAI-compatible 上游也会重排。
  • TTL 选择“自动”时不发送 ttl；选择“5 分钟”或“1 小时”时，所有 marker 统一使用对应窗口。
  • TTL 选择“手动”时，[[CACHE_BREAK]] 使用 ttl: "1h"，[[CACHE_BREAK_SHORT]] 使用 ttl: "5m"。1h 断点必须排在所有 5m 断点之前。

渠道与供应商

  • 渠道 Profile 会保存名称、Base URL、上游格式和高级配置，不保存 API Key。
  • Pioneer 是默认自定义渠道；OpenRouter、Anthropic、Vertex、Bedrock 是内置模板。
  • OpenRouter 的“锁定供应商”会写入 provider 参数，可选择常见供应商，也可以填写自定义供应商名。
  • Vertex / Bedrock 卡片目前是 Profile 模板，不包含 Google Auth 或 AWS SigV4 签名；需要真实云鉴权时建议先走兼容供应商或自定义代理。

高级配置

  • 包含主体参数：把 JSON 对象深度合并到最终请求体，同时支持 OpenAI-compatible 和 Anthropic native 上游；请只填写目标协议支持的字段。
  • 排除主体参数：按字段路径删除请求体字段，例如 stream_options 或 metadata.trace_id。
  • 包含请求头：添加 / 覆写非密钥 header，例如 HTTP-Referer、X-Title。
  • 排除请求头：发送上游前删除指定 header，例如 x-real-ip、x-forwarded-for。

高级配置按当前渠道保存。Authorization、x-api-key、Cookie、token、secret、password 等密钥类字段会被拒绝保存。

全局缺省值来自项目根目录的 default-gateway-settings.json；当 gateway-settings.json 缺少全局参数时会回退到该文件，但不会从默认文件导入渠道 Profile。

诊断

  • 请求诊断的开关会持久保存；捕获到的请求正文仍只保存在内存中，重启后日志清空，但若开关为开启会继续记录新请求。
  • 诊断会记录最终请求体，可能包含私密提示词；不要公开导出的诊断 JSON。
  • 可通过诊断查看最终请求体、全部缓存断点、每个断点的选择原因、Prefix hash、suffix hash 和上游缓存用量。
  • 最终请求体中的每个提示词块都会在消息标题栏显示 10 位 SHA-256 短哈希；与同渠道、同协议、同模型的上一次请求不同或新增的块会加粗，完整哈希保留在诊断 JSON。
  • 请求列表和 Usage 页会按三行显示输入、输出、缓存创建、缓存命中和缓存命中率；原始 Usage JSON 仍保留在统计行下方。

常见问题

  • Mac 打不开 bat？ .bat 只适用于 Windows。macOS / Linux 请用 chmod +x start-gateway.sh 后运行 ./start-gateway.sh。
  • 请求 404 或路径不对？ 酒馆 Base URL 优先填写 http://127.0.0.1:8788/v1。
  • 请求日志要一直开吗？ 不建议。开关会跨重启保持，诊断又会记录最终请求体；排查结束后请主动关闭并清空日志。
  • 缓存没命中？ 确认蓝灯世界书在缓存 marker 之前、绿灯世界书在它之后；必要时开启 Prefix 锁定排查前缀漂移。
  • 使用数据库会影响缓存吗？ 数据库本身不影响缓存，官方渠道验证正常；若数据库蓝灯条目会随填表更新，请把全局注入位置改到缓存点后面，例如角色后、系统。
  • 上游不支持 1h TTL？ 在“缓存策略”里切换为“5 分钟”或“自动”；手动模式下不要使用会生成 1h 的 [[CACHE_BREAK]]。
